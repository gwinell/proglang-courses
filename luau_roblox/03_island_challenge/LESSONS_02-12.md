## Занятие 2. Переменные — имена для значений

**Цель:** ученик создаёт локальные переменные и меняет значения объекта через код.  
**Подготовка:** один Part в `Workspace`, назван `Coin`; пустой Script в `ServerScriptService`.

**Ход:** 0–8 показать несколько монет и спросить, что у них общее; 8–18 объяснить переменную как именованное значение; 18–35 совместно набрать пример; 35–60 изменить имя, цвет и цену монеты; 60–78 обменяться проектами и предсказать вывод; 78–90 exit ticket.

```lua
local coin = workspace.Coin
local coinName = "Золотая монета"
local points = 5

coin.Color = Color3.fromRGB(255, 210, 40)
print(coinName)
print("Очки за монету:", points)
```

**Объяснение:** `local` создаёт имя, `=` кладёт значение в эту «коробку», `coin` ссылается на объект, а точка обращается к его свойству. Строка — текст в кавычках, число — без кавычек.  
**Задание:** создать две переменные и поменять цвет/очки.  
**Проверка:** «Что изменится, если заменить `5` на `10`? Что в коде является именем объекта?»  
**Отладка:** убедиться, что Part действительно называется `Coin`; имена чувствительны к регистру; проверить кавычки и Output.

- **8–20:** объяснить событие и обработчик на примере дверного звонка.

```lua
local pad = script.Parent

local function onTouched(otherPart)
	pad.Color = Color3.fromRGB(80, 200, 120)
	print("Платформу коснулся объект:", otherPart.Name)

```

**Важно:** объект-скрипт должен быть дочерним объектом платформы. `Touched` может срабатывать несколько раз из-за частей персонажа — это повод для наблюдения, не ошибка в первом эксперименте.

	platform.Transparency = 1

## Занятие 5. Условия — безопасная и опасная поверхность

**Цель:** использовать `if` и `then`, чтобы реагировать на персонажа.

```lua
local trap = script.Parent

local function onTouched(otherPart)
	local character = otherPart:FindFirstAncestorOfClass("Model")
	if not character then
		return
	end

	local humanoid = character:FindFirstChildWhichIsA("Humanoid")

	if humanoid then
		trap.Color = Color3.fromRGB(255, 70, 70)
		print("Игрок коснулся ловушки")
	end
end

trap.Touched:Connect(onTouched)
```

**Ход занятия (90 минут):**

- **0–8:** показать ловушку и спросить, как отличить игрока от падающего куба.
- **8–20:** сформулировать правило словами: «если модель принадлежит персонажу и в ней есть Humanoid…».
- **20–40:** разобрать `FindFirstAncestorOfClass`, защиту `if not character` и проверку Humanoid.
- **40–65:** вместе добавить реакцию ловушки; проверить персонажем и обычным Part.
- **65–80:** ученики меняют цвет и проверяют крайние случаи с вложенной деталью персонажа.
- **80–90:** exit ticket: объяснить, почему проверяем модель и Humanoid.

Проверка Humanoid помогает отличать персонажа от обычного Part.  
**Проверка:** ученик объясняет, что такое условие и почему `if humanoid then` срабатывает только при наличии Humanoid.  
**Отладка:** проверить, что `FindFirstChildWhichIsA` написан точно и что Script находится внутри ловушки.

## Занятие 8. Счёт игрока в текущей сессии

**Цель:** создать `leaderstats` на сервере и начислять очки при касании монеты.

**Структура Explorer:** `ServerScriptService > LeaderstatsScript` и `Workspace > Coin > CoinScript`. Монета в этом упрощённом варианте общая для сервера: её первым собирает один игрок, после чего она исчезает для всех. Объясните это заранее; персональные монеты для каждого игрока — отдельная расширенная механика.

**Часть A — Script в `ServerScriptService`:**

```lua
local Players = game:GetService("Players")


local function createStats(player)
	if player:FindFirstChild("leaderstats") then
		return
	end

	local leaderstats = Instance.new("Folder")
	leaderstats.Name = "leaderstats"
	leaderstats.Parent = player

	local points = Instance.new("IntValue")
	points.Name = "Points"
	points.Value = 0
	points.Parent = leaderstats
end

Players.PlayerAdded:Connect(createStats)

-- Проверяем и игроков, подключившихся до запуска скрипта.
for _, player in Players:GetPlayers() do
	createStats(player)
end
```

**Часть B — Script внутри Part `Coin`:**

```lua
local Players = game:GetService("Players")
local coin = script.Parent
local collected = false

coin.Touched:Connect(function(hit)
	if collected then
		return
	end

	local player = Players:GetPlayerFromCharacter(hit.Parent)
	if not player then
		return
	end

	local leaderstats = player:FindFirstChild("leaderstats")
	if leaderstats then
		local points = leaderstats:FindFirstChild("Points")
		if points then
			collected = true
			points.Value += 5
			coin:Destroy()
		end
	end
end)
```

**Ход занятия (90 минут):**

- **0–8:** показать таблицу игроков и вопрос: где хранится счёт каждого игрока?
- **8–20:** объяснить `PlayerAdded`, папку `leaderstats` и `IntValue` на схеме Explorer.
- **20–40:** создать первую часть скрипта; запустить Play и увидеть Points.
- **40–55:** добавить Part `Coin` и второй Script по схеме Explorer; объяснить, что монета общая.
- **55–70:** проверить касание; обсудить, почему сервер начисляет очки, а не клиент.
- **70–80:** включить локальный сервер с двумя тестовыми игроками через вкладку `Test` (названия кнопок могут меняться) и увидеть, что очки у игроков отдельные, но общая монета достаётся первому.
- **80–90:** exit ticket: кто получает очки и почему монета исчезает для второго игрока?

**Пояснение:** это счёт в рамках запущенной сессии, он не сохраняется после выхода.  
**Проверка:** два тестовых игрока имеют отдельные значения; монета не начисляет очки повторно.

## Занятие 9. Контрольная точка и финиш

**Цель:** распознать игрока через `Players:GetPlayerFromCharacter` и назначить SpawnLocation.

**Структура Explorer:** `Workspace > Checkpoint` (объект класса `SpawnLocation`) и `CheckpointScript` внутри него. Оставьте контрольную точку в `Workspace`, включите `Anchored` и `Neutral`, чтобы она была доступна игрокам независимо от команды. Название `Checkpoint` задаётся в Explorer.

```lua
local Players = game:GetService("Players")
local checkpoint = script.Parent
checkpoint.Anchored = true
checkpoint.Neutral = true

checkpoint.Touched:Connect(function(hit)
	local player = Players:GetPlayerFromCharacter(hit.Parent)
	if player then
		player.RespawnLocation = checkpoint
		print(player.Name, "активировал контрольную точку")
	end
end)
```

- **20–40:** создать `SpawnLocation` в `Workspace`, закрепить, включить `Neutral`, проверить положение.
- **40–55:** вложить Script, добавить получение игрока и назначение `RespawnLocation`.
- **55–70:** проверить касание, упасть в тесте и проверить возрождение.
- **70–80:** пары добавляют вторую точку и объясняют, какая становится последней активной.
- **80–90:** exit ticket: назвать класс объекта и свойство, которое задаёт точку возрождения.

**Проверка:** ученик демонстрирует, что после касания возрождается у последней контрольной точки.  
**Отладка:** проверить класс объекта (именно SpawnLocation), что он остаётся в Workspace, `Anchored`, `Neutral`, имя и место Script. Если точка активируется, но персонаж появляется не там, перепроверьте настройки SpawnLocation и повторите тест после перезапуска.

## Занятие 11. Клиент–сервер и RemoteEvent

**Цель:** проследить, как клиент отправляет RemoteEvent, а сервер получает запрос. Это демонстрация направления сообщения, а не полноценная система проверки игровых действий.

**Подготовка:** создать `RemoteEvent` с именем `WelcomeRequest` внутри `ReplicatedStorage`.

**Script в `ServerScriptService`:**

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local welcomeRequest = ReplicatedStorage:WaitForChild("WelcomeRequest")

welcomeRequest.OnServerEvent:Connect(function(player)
	print("Сервер получил запрос от", player.Name)
end)
```

**LocalScript внутри TextButton в ScreenGui:**

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local button = script.Parent
local welcomeRequest = ReplicatedStorage:WaitForChild("WelcomeRequest")

button.Activated:Connect(function()
	welcomeRequest:FireServer()
end)
```

**Ход занятия (90 минут):**

- **0–8:** объяснить роли клиента и сервера через пример «игрок просит, сервер решает».
- **8–20:** нарисовать путь сообщения и разобрать, зачем нужен RemoteEvent.
- **20–40:** создать RemoteEvent в ReplicatedStorage и серверный Script с обработчиком.
- **40–55:** создать TextButton и LocalScript; связать нажатие с `FireServer()`.
- **55–70:** запустить тест с локальным сервером и двумя игроками; найти сообщения в Output сервера.
- **70–80:** ученики пересказывают путь события от кнопки к серверу.
- **80–90:** exit ticket: объяснить, почему клиентский запрос нельзя считать доказательством права на награду.

**Проверка:** ученик показывает, какой код выполняется на клиенте и сервере.  
**Важно:** текущая кнопка только отправляет запрос, сервер печатает имя игрока. Если запрос будет менять счёт или состояние игры, сервер обязан сам проверить условия и принять решение.
