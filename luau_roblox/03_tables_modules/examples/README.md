# Примеры к уроку 3

[Открыть урок «Таблицы и организация кода»](../03_tables_and_modules.md)

## 1. Таблицы: один обычный Script

[01_tables_demo.luau](01_tables_demo.luau) содержит 17 примеров из урока. Скопируй его целиком в Lesson03 — обычный Script в ServerScriptService — и открой Output. Каждый блок подписан строкой вида `--- array_read ---`.

Примеры отделены конструкциями `do ... end`: тело выполняется один раз, а локальные переменные разных примеров не смешиваются. Если запускаешь отдельный пример из текста урока, оболочка не нужна.

[Образец вывода](01_tables_demo.expected.txt) показывает результат по блокам. **В блоке dictionary_iteration порядок двух строк не задан**: potion и rope могут поменяться местами. Это правильный результат. В остальных блоках порядок важен. Время, имя Script и пометка Server в Studio не входят в образец.

## 2. Первый ModuleScript: два объекта

После Stop отключи Lesson03 и создай папку ModulePractice в ServerScriptService. В неё добавь:

| Файл в репозитории | Имя и тип объекта Studio |
| --- | --- |
| [module_practice/Greeting.luau](module_practice/Greeting.luau) | Greeting — **ModuleScript** |
| [module_practice/Main.server.luau](module_practice/Main.server.luau) | Main — **Script** |

Замени код каждого объекта соответствующим файлом целиком. Имена в Explorer указывай без расширений. Запусти новый Test: [ожидаемый вывод](module_practice/Main.expected.txt) содержит одно сообщение загрузки, приветствие и true.

Оба require в Main обращаются к одному соседнему ModuleScript. Если объекты лежат в разных папках, путь script.Parent.Greeting больше не соответствует показанной структуре.

## 3. Лавка: три объекта

Останови Test и отключи Main предыдущего опыта. В ServerScriptService создай папку ShopLesson с тремя объектами:

| Файл | Имя и тип объекта Studio | Роль |
| --- | --- | --- |
| [shop/Catalog.luau](shop/Catalog.luau) | Catalog — **ModuleScript** | Данные товаров. |
| [shop/CartMath.luau](shop/CartMath.luau) | CartMath — **ModuleScript** | Функция расчёта. |
| [shop/Main.server.luau](shop/Main.server.luau) | Main — **Script** | Подключение модулей, корзина и сообщения. |

Каталог и функция не подключают друг друга: их получает Main. После запуска сравни Output с [shop/Main.expected.txt](shop/Main.expected.txt). Затем проверь варианты из таблицы основного урока. Каждый опыт начинай после Stop, возвращая исходные настройки перед следующей проверкой.

Файлы .luau в папке на компьютере сами по себе не создают ModuleScript в Explorer. Для этого урока объекты создаются вручную, затем в них копируется код. Плагины синхронизации и Rojo устанавливать не требуется.

## Что проверено при подготовке

- Все 17 самостоятельных примеров таблиц выполнены официальным [Luau CLI 0.745](https://github.com/luau-lang/luau/releases/tag/0.745). Их вывод сравнен с текстом урока; для словаря сравнивался состав строк, а не порядок.
- Общий файл примеров выполнен целиком.
- Код Greeting и двух модулей лавки выполнен без изменения их содержимого. Для запуска главных скриптов в CLI только выражения `require(script.Parent.Name)` заменялись на файловые `require("./Name")`.
- Проверены однократная загрузка Greeting в CLI, одинаковый возвращаемый объект при повторном подключении и итог основного примера лавки.
- Проверены пять изменений лавки из урока, повторяющиеся товары, бесплатный товар с ценой 0, неизвестный товар после известного и повторный вызов расчёта. Корзина и цены после расчёта остались прежними.
- Проверено, что неисправный пример черновика из домашней работы действительно меняет исходный список.

**Граница проверки:** CLI не содержит дерева объектов Roblox и не выполняет вариант require с объектом ModuleScript. Проверены логика таблиц, содержимое модулей и файловое подключение в CLI. Расположение объектов и запуск именно в движке Roblox нужно проверить в Studio по инструкции урока. Правила ModuleScript и кеширования в Roblox сверены с [официальным описанием класса](https://github.com/Roblox/creator-docs/blob/c8f5276703948ef4868c9b9fd44fae619dbe2f11/content/en-us/reference/engine/classes/ModuleScript.yaml).
