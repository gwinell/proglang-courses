| Файл | Тип в Studio | Обязанность |
| --- | --- | --- |
| [GameRules.luau](GameRules.luau) | ModuleScript `GameRules` | Баланс, срок урона, продвижение и ограничение лечения |

| [Main.server.luau](Main.server.luau) | Серверный Script `Main` | Игроки, статистика, проверка контакта и события |

Создай новый Baseplate. В `ServerScriptService` добавь папку `MechanicsLesson`, а в неё два ModuleScript и Script с именами из таблицы. Замени их содержимое полным кодом файлов. Не добавляй расширения к именам объектов Studio. Старые скрипты статистики отключи: существующий `leaderstats` пример не перезаписывает.

Play создаёт `Workspace.Lesson05Mechanics`. В Output ожидается `Механики готовы: Coins, Stage, Hazard, Medkit`. После сообщения сделай Reset: настройка `RespawnLocation` относится к следующему появлению, а текущий персонаж мог появиться раньше у исходного SpawnLocation Baseplate.

| Проверка | Ожидается |
| --- | --- |
| Новая Play-сессия | Coins 0, Stage 0; назначен Start |
| Одна монета | +5 один раз, скрыта на 4 секунды или чуть дольше, затем доступна новым касанием |
| Два разных игрока у Hazard | Отдельный срок удара для каждого, урон 25, пауза 1.5 секунды |
| Checkpoint2, затем Checkpoint1 | Stage 2, следующее появление у второго |
| Смерть / Reset | Coins и Stage остаются в текущей сессии |
| Полностью здоровый персонаж у Medkit | Предмет остаётся |
| Повреждённый персонаж у Medkit | До +30, максимум MaxHealth; новый предмет после 6 секунд или чуть дольше |
| Одна монета / аптечка, два игрока | Один принятый подбор; победитель заранее не задан |
| Stop, затем Play | Новая сессия, прогресс сброшен |

Монета остаётся тем же Part, `CanTouch` не выключается. Аптечка уничтожается, а затем создаётся заново. Не считай стояние внутри предмета новым касанием: отойди и войди снова. Для проверки здоровья учитывай ForceField и стандартную регенерацию. В учебных SpawnLocation `Duration = 0`, но исходная площадка Baseplate может иметь другие настройки.

Checkpoint допускает пропуск этапа 0 → 2. Площадки имеют постоянные цвета, у каждого игрока личный RespawnLocation. Все цифры задаёт сервер. Запись сессии удаляется на PlayerRemoving. Данные между посещениями не сохраняются.

## Автоматическая проверка и её пределы

Файлы компилируются официальным CLI Luau 0.745. [Тесты](verification/test_examples.luau) читают эти же три файла через автоматически сформированный [модуль исходников](verification/Sources.luau), сверенный по SHA-256 в [отчёте](verification/report.json). [Модель API](verification/RobloxModel.luau) позволяет явно посылать события и двигать тестовое время; она не является движком Roblox.

Из этой папки командой CLI `luau verification/test_examples.luau` можно повторить проверки. При изменении трёх файлов сначала обнови снимок исходников через `python3 verification/build_sources.py`, затем запусти тесты. В Studio эти проверочные файлы не нужны.

Автоматически проверяются числа, независимость игроков и предметов, повторные вызовы, ограничения здоровья, назначение RespawnLocation, уничтожение/создание предмета и очистка сессии. Не проверяются реальные физические контакты, интерфейс, сеть, движковый планировщик и настоящее возрождение персонажа. Подключённой Studio при подготовке не было, полный Play-тест не заявляется. Сценарии одного и двух клиентов находятся в основном уроке.
