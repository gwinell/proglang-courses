# Практикумы: сначала план, потом код

Материал рассчитан на три короткие встречи после циклов, коллекций и функций соответственно. На каждой встрече ученик сначала разбирает задачу словами и вручную, а затем пишет код. Не используйте приём, который ещё не объяснён в курсе.

## Рабочий лист алгоритма

Для каждой задачи ответь на вопросы:

1. Что дано? Как выглядят входные данные?
2. Что нужно получить и в каком формате?
3. Какие значения разрешены? Что будет на границах?
4. Посчитай один маленький пример вручную.
5. Что повторяется? Какое действие выполняется для каждого элемента?
6. Какие значения нужно помнить: сумму, количество, лучший результат, ответ?
7. Запиши план обычными словами.
8. Переведи каждое действие в Python.
9. Проверь обычный пример, границу и случай без подходящих элементов.
10. Объясни, почему программа заканчивается и почему ответ верен.

### Практикум 1. Сумма и количество после изучения `for`

**Сюжет.** В списке записано число посылок, доставленных курьером в каждый из `n` дней. Нужно узнать общее число посылок и сколько дней было с доставкой не меньше пяти.

**Вход:** сначала `n`, затем `n` целых чисел по одному на строку. Гарантируется `1 ≤ n ≤ 100`, `0 ≤ deliveries ≤ 20`.

**Выход:** общая сумма и число подходящих дней через пробел.

До кода заполни таблицу для `n = 4` и значений `2, 5, 0, 7`. Нарисуй две независимые переменные состояния: сумма начинает с нуля и изменяется каждый день; счётчик начинается с нуля и растёт только при выполнении условия. Затем напиши пошаговый план.

**Проверки:** четыре дня дают `14 2`; одно значение `4` даёт `4 0`; одно значение `5` даёт `5 1`.

**Перенос:** измени условие на «строго больше пяти». Скажи, какой пример различает старую и новую версию.

### Практикум 2. Выбор и частоты после изучения коллекций

**Сюжет.** В списке времени доставки в минутах нужно найти самое быстрое время и посчитать, сколько доставок были не дольше 30 минут.

Гарантируется, что список непустой, поэтому первое время можно временно принять за лучшее. Для нового значения сравни его с лучшим и замени лучший, только если новое значение меньше. Для количества отдельно используй счётчик.

Вручную разберись со значениями `42, 30, 30, 51` и `8`. Запиши, как меняется лучший ответ после каждого элемента, сколько элементов прошло ограничение, и что произойдёт при равенстве.

**Тесты:** `42, 30, 30, 51` → минимум `30`, подходящих `2`; `8` → минимум `8`, подходящих `1`.

**Граница:** отдельно обсуди, почему алгоритм с начальным минимумом `0` не подходит для положительных времён.

**Перенос:** посчитай количество появлений заданного числа. Не создавай таблицу частот, если достаточно одного счётчика.

### Практикум 3. Разделение задачи на функции после изучения функций

**Сюжет.** Программа принимает оценки команды и выводит среднюю оценку и количество оценок не ниже заданного порога. Раздели ответственность на функции: одна считает сумму, другая — число прошедших порог, третья объединяет вычисления и печатает результат.

Пока вход непустой. Реши пример `3, 4, 5` с порогом `4`: среднее `4.0`, прошли `2` человека. Затем отдельно проверь одну оценку и случай, когда никто не прошёл.

До кода запиши для каждой функции: что она получает, что возвращает, меняет ли список. Не печатай результат внутри функции, которая по условию должна вернуть число.

**Перенос:** замени проходной порог, не меняя вычисление среднего. Объясни, какие функции пришлось изменить и почему.
