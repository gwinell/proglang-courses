# Контрольные точки и оценивание курса Python

Этот документ дополняет учебные задания и проекты четырьмя короткими контрольными точками. Они помогают понять, что ученик способен применить материал самостоятельно. Успешный запуск примеров в блокноте сам по себе не считается подтверждением освоения.

Полные независимые варианты для четырёх точек — с кодом для чтения и исправления, новой задачей с форматом входа/выхода и точными критериями — находятся в отдельном [банке контрольных](independent_variants.md). Этот файл задаёт общие навыки и шкалу; банк содержит задания для выдачи ученикам.

## Общие правила

- Проводить контрольную точку после завершения соответствующего блока и до перехода к следующему крупному блоку.
- Давать задания на уже изученных конструкциях. Если новый материал блока проверяется, сначала дать короткую тренировочную задачу.
- Просить ученика проговорить план до написания кода. План может быть кратким и состоять из обычных слов.
- Разрешать корректные альтернативные решения, если условие прямо не требует определённый способ.
- Не оценивать скорость как основной показатель. Записывать, где ученик потерялся: условие, план, синтаксис, проверка или запуск.
- При затруднении назначать конкретное повторение из реестра навыков, а затем предлагать параллельную задачу с новым сюжетом.

## Общая шкала для отдельного задания

| Балл | Наблюдаемое выполнение |
|---:|---|
| 0 | Пока не может начать даже после повторного чтения условия; объяснить затруднение и вернуться к предпосылкам. |
| 1 | Решает после содержательной подсказки или вместе с преподавателем; навык требует повторения. |
| 2 | Решает самостоятельно, проверяет обычный и граничный случай, может объяснить ключевой шаг. |
| 3 | Самостоятельно выбирает ясный план, находит дополнительный особый случай и корректно меняет решение при небольшом изменении требований. |

Не суммировать баллы в единственный ярлык «знает/не знает». Для каждого навыка отмечать статус: **самостоятельно**, **с подсказкой**, **повторить**. Ошибка синтаксиса при верном плане фиксируется отдельно от ошибки в алгоритме.

## Контрольная точка 1. Ввод, числа и условия

**Место:** после первого блокнота о числах и условиях.

**Проверяемые навыки:** чтение `input()`, преобразование текста к числу, арифметика, целочисленное деление и остаток, сравнения, границы `if/elif/else`, `and/or`, форматирование результата.

| Часть | Задание ученику | Что наблюдать |
|---|---|---|
| Чтение кода | Предсказать результат программы с `input()`, `int()` и повторным присваиванием. | Различает строку и число; объясняет, какое значение хранится после присваивания. |
| Исправление | В условии для скидки исправить ошибку на точной границе и проверить два соседних значения. | Проверяет равенство границе, а не только далёкий обычный случай. |
| Самостоятельно | Авторская задача из карточек ДЗ этого блока: по двум целым числам вычислить результат с использованием деления/остатка и условие выбора. | Переписывает вход и формат выхода словами до кода; решение не содержит лишних приглашений ко вводу, если они не предусмотрены форматом. |
| Объяснение | Почему результат `input()` сначала текст? Чем `/` отличается от `//`? | Объяснение своими словами с небольшим примером. |

**Повторить при затруднении:** `input` → `int`/`float`, порядок вычисления выражения, равенство и границы условия, смысл `//` и `%`.

## Контрольная точка 2. Циклы и последовательности

**Место:** после `for`, `while`, списков и вложенных циклов.

**Проверяемые навыки:** `range`, счётчик и накопитель, завершение `while`, перебор последовательности, индекс и значение, `append`, простая фильтрация, порядок вложенного перебора.

| Часть | Задание ученику | Что наблюдать |
|---|---|---|
| Чтение кода | Заполнить таблицу значений переменных после каждой итерации короткого цикла. | Отличает начальное значение от обновления и выхода. |
| Исправление | Исправить бесконечный или пропускающий последний элемент цикл. | Находит место ошибки по изменению состояния и проверяет завершение. |
| Самостоятельно | Обработать небольшой список: посчитать подходящие элементы и собрать новый список, не удаляя элементы на ходу. | Сам выбирает счётчик/накопитель, проверяет пустой список и один подходящий элемент. |
| Объяснение | Для маленькой таблицы предсказать порядок внешнего и внутреннего циклов. | Может назвать текущие строку и столбец и объяснить число проходов. |

**Повторить при затруднении:** границы `range`, изменение счётчика, `break`/`continue`, индексация, пустая коллекция, различие `append` и присваивания по индексу.

## Контрольная точка 3. Строки, коллекции и функции

**Место:** после словарей и базовых функций.

**Проверяемые навыки:** методы строк, разбиение текста, `in`, список/кортеж/словарь под задачу, подсчёт частот, параметры, аргументы, `return`, область видимости.

| Часть | Задание ученику | Что наблюдать |
|---|---|---|
| Чтение кода | Проследить, что функция получает и что возвращает, отличить `print()` от `return`. | Не принимает вывод на экран за результат функции. |
| Исправление | Исправить функцию подсчёта или поиска, которая неверно работает при пустом вводе или повторяющихся значениях. | Сначала уточняет поведение для этих случаев. |
| Самостоятельно | Написать небольшую функцию, которая принимает текст/список и возвращает результат в оговорённом формате. | Не печатает вместо возвращения значения; имя не затеняет встроенные функции. |
| Объяснение | Почему счётчики слов удобно хранить в словаре? Когда `split()` отличается от `split(" ")`? | Связывает структуру данных с действием и примером. |

**Повторить при затруднении:** `strip`/`lower`/`split`/`join`, `in`, `dict.get`, параметры и аргументы, локальные переменные, возвращаемое значение, отсутствие результата `None`.

## Контрольная точка 4. Разбиение программы, состояние и проверка

**Место:** после функций, обработки ошибок, файлов и ООП; отдельные вопросы задавать только после изучения соответствующей темы.

**Проверяемые навыки:** декомпозиция небольшой задачи, повторные вызовы функций, изменение/сохранение состояния, чтение traceback, безопасное открытие файла, независимое состояние экземпляров, проверка результата.

| Часть | Задание ученику | Что наблюдать |
|---|---|---|
| Чтение кода | По короткому проекту описать путь данных от ввода до результата/файла. | Видит границы функций/методов и назначение состояния. |
| Отладка | В пошаговом режиме найти, на каком шаге неверно меняется переменная или атрибут. | Проверяет гипотезу через значения, а не меняет строки случайно. |
| Самостоятельно | Разбить мини-задачу на две-три функции, реализовать основную версию и проверить несколько входов. | Выбирает понятные параметры и возвращаемые значения, повторно использует логику. |
| Объяснение | Как проверить, что функция не испортила исходный список? Почему два объекта должны иметь независимые коллекции? | Приводит проверку до/после и объясняет принадлежность данных. |

**Повторить при затруднении:** чтение traceback, `try/except` на изученных исключениях, `with open(..., encoding="utf-8")`, возврат из функции, атрибут экземпляра, вход/выход метода, простая проверка результата.

## Короткая запись результата

После каждой контрольной точки преподаватель заполняет таблицу для ученика. Записывать один наблюдаемый факт, а не только оценочный ярлык.

| Дата/точка | Навык | Статус | Наблюдение | Следующая практика |
|---|---|---|---|---|
|  | `range` и границы | повторить | Пропустил последнее значение в диапазоне | Новая задача на число шагов и таблица итераций на следующем занятии |
|  | `return` | с подсказкой | Верное вычисление, но результат печатался внутри функции | Переделать одну функцию так, чтобы вызывающий код мог использовать результат |

Индивидуальная запись — рабочий инструмент преподавателя. В публичные материалы не вносить реальные имена, оценки и персональные сведения учеников.
