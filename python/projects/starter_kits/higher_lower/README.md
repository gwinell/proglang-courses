# Стартовый набор: «Кто популярнее?»

Идея адаптирована по проекту Higher Lower Game, Day 14 курса 100 Days of Python. В этой версии используются вымышленные профили, локальный JSON и консольный интерфейс; интернет, API и сторонние данные не нужны. См. описание проекта в [проектной паре 4](../../04_dictionaries.md).

## Файлы

- `profiles.json` — восемь готовых профилей с уникальными числами читателей.
- `stage_1_read.py` — запускаемый первый этап: чтение и проверка структуры набора.
- `stage_2_compare.py` — запускаемый этап сравнения выбранной пары.
- `main.py` — каркас полной игры; этапы `TODO` выполняются учеником.

Запускай команды из этой папки: `python stage_1_read.py`, затем `python stage_2_compare.py A` или `python stage_2_compare.py B`. Код рассчитан на Python 3.10+ и стандартную библиотеку.

## Этапы работы

1. Запусти `stage_1_read.py`; объясни, почему после `json.load` получен список словарей.
2. Запусти `stage_2_compare.py A` и `... B`; проверь обе ветки и случай равного выбора (в данных его нет).
3. В `main.py` допиши показ карточки без поля `readers`, получение ответа и проверку допустимых значений A/B.
4. Добавь счётчик правильных ответов. При неверном ответе заверши раунд и покажи итог.
5. После правильного ответа оставляй победивший профиль на месте A, а новым кандидатом выбирай ещё не использованный профиль.
6. Заверши игру после исчерпания списка. Проверь, что число очков не больше числа сравнений.
7. Для повторяемой проверки временно используй последовательность профилей из порядка файла; случайную перестановку добавляй только после проверки логики.

## Приёмка

- Числа `readers` не видны игроку до выбора.
- Каждый новый профиль предлагается не более одного раза.
- Верный ответ добавляет ровно одно очко; неверный не добавляет.
- При продолжении предыдущий победитель становится кандидатом A.
- Пустой набор корректно завершает игру без обращения к индексу списка.
- Минимум два запуска с разными ответами описаны в таблице ручной проверки.
